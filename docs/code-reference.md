# Code reference

Detailed behavior of the engine, network files, and build. Read the relevant section when changing those components. For feature design and evolution concepts, see [Go features](features.md) and [The evolving genome](genes.md).

## Layout

- `engine/`: `evo`, a GTP engine built on Brown's board code (`brown.c`, `gtp.c`) plus the network move policy (`generate_move.c`). `engine/rules_test.c` (`make test` in `engine/`) pins Brown's rules, the move filter, and the move choice with feature weights, and `enginetest.sh` and `gtp_test.c` check them through GTP `play`:
  - Captures remove every neighboring opponent string left without a liberty. Ko is simple ko: only an immediate single-stone recapture is refused, and any other move or a pass ends it.
  - `legal_move` and GTP `play` accept suicide; the suicided string is removed at once.
  - `genmove` scores each point as the network's output plus B, the network's feature weights: for each move feature of its groups that is 1 at the point, that feature's weight (`ann_features.weights`, in `ANN_FEATURES`' order); the pass output gets nothing. Without groups the scores are the outputs. It then plays the highest-scoring point that is legal, not suicide, and not the opponent's suicide point (in effect an own eye) unless it touches an opponent stone: `move_allowed` in `features.c`, which the move features use too. It passes when nothing is allowed or the pass output scores at least as high, so a tie (common with saturated cached sigmoid outputs) passes.
  - `generate_move(ann, features, &i, &j, color)` (`features` NULL means no groups) fills the inputs with `feature_inputs` for the network's groups, runs the network, adds B, and picks with `find_and_set_best_move`, so for a network without groups the moves are those from before the features. `ann_fits_board(ann, features, size)` checks the inputs against `ann_layout_inputs` of the feature set on that board and the outputs against its points plus pass. The input buffer holds `GENERATE_MOVE_MAX_INPUTS`, every group on 23×23 (6,350; `rules_test` checks it against `ann_layout_inputs`). evo (`network_features` in `interface.c`, `place_free_handicap` included) and the arena (each loaded network's `features`) pass the features read with the network. `generate_move.c` takes the network as an argument and owns its input buffer, so `brown.o` + `features.o` + `generate_move.o` + `lib/libann.a` link without the GTP code (`gtp.o`, `interface.o`). `rules_test` links that way, which keeps it so, and checks that the move choice refuses exactly the points `move_allowed` refuses. `ann` stays a global of `interface.c` for evo's GTP commands. Start a game with `new_game()`, which also clears Brown's ko point (GTP `clear_board` and `init_brown` use it); `clear_board()` empties the board and forgets the last move but keeps the ko point.
  - Brown records the last move: `play_move` (a pass is `play_move(-1, -1, color)` or `play_pass(color)`) stores the point or pass and its colour, and `last_move(&i, &j, &color)` returns `LAST_MOVE_NONE`, `LAST_MOVE_PASS`, or `LAST_MOVE_POINT` (i, j −1 for a pass or none, colour `EMPTY` for none; NULL arguments allowed). A suicide is still the last move, at a point that is empty again. `new_game` and `clear_board` reset it; handicap stones are not moves, so `place_fixed_handicap` (in `brown.c`) and GTP `set_free_handicap` and `place_free_handicap` (in `interface.c`) call `clear_last_move()` after placing them with `play_move`, and `set_free_handicap`'s error paths call `clear_board`. GTP `play`, `genmove` (pass included), and the arena play through `play_move`, so they need nothing else.
  - `brown_save(&s)`/`brown_restore(&s)` copy Brown's whole game state (board, string links `next_stone`, ko point, last move; not `board_size`, `komi`, or the final status) into and out of a caller's `brown_state` (about 4 kB, arrays sized for `MAX_BOARD`). A trial move is save, `play_move`, read, restore; a snapshot can be restored any number of times, and callers may hold several. `rules_test.c` checks that a restore after a trial capture and a trial ko capture gives back the same board, strings, legal moves (the ko), and last move.
  - `features.c` (`features.h`; include `brown.h` first) computes the features from Brown's board for the player to move; it needs only `brown.o` and `lib/libann.a` (the layout's counts), and `features_test` links it so. `generate_move` uses it for every network's inputs and for B.
    - Move features, bits `FEATURE_BIT(f)` in the input layout's order: `FEATURE_HANE`, `_CUT`, `_EDGE` (group shapes), `_CAPTURE`, `_SELF_ATARI`, `_SAVES_ATARI` (tactics), `_NEAR_LAST` (last_move); `MOVE_FEATURES` counts them, and `group_features(groups)` gives a group mask's bits. All are 0 wherever `move_allowed` is false. capture: the move captures (ko captures too); self_atari: it captures nothing and leaves its chain one liberty; saves_atari: an own chain in atari before has two or more liberties after, by extending or by capturing, touching it or not; near_last: one of the 8 points around the opponent's last stone, only when the last move was the opponent's stone and it is still on the board (not after a pass, an own move, a suicide, or handicap stones). `move_features_board(color, wanted, bits)` computes the `wanted` bits of the whole board in one pass; a trial move (undone with `brown_restore`, so the board, ko point, and last move stay) happens only where a tactical feature can be 1 (a capture, a touched own chain in atari, or fewer than two empty neighbours). With every group, `feature_inputs` takes about 5 µs per board on 9×9 and 19 µs on 19×19 (26 Sep 2026). `move_features_at(i, j, color)` computes the whole board for one point, so use it only in tests. `chain_liberties(i, j)` is 0 at an empty point.
    - The group bits (`ANN_GROUP_SHAPES`, `_TACTICS`, `_LAST_MOVE`, `_LIBERTIES`, `ANN_GROUPS_ALL`) and the layout's counts (`ann_feature_count(groups)`, the move features F; `ann_layout_inputs(groups, points)`; both -1 for an unknown bit) live in `lib/ann.h`, since the `.ann` reader needs them. `feature_inputs(groups, color, inputs, bits)` fills `[komi][N stones][F×N move features][3×N liberties][N last_move][opponent_passed]`, only the groups present: liberties has +1 (own) or −1 (opponent) at each stone in the plane for its chain's 1, 2, or 3+ liberties; the last_move plane is 1 at the stone near_last goes by; opponent_passed is 1 after the opponent's pass. Komi and stones come first for every feature set, so `features none` gives the inputs from before the features. It returns the count, and fills `bits` with the groups' move features unless NULL.
    - The shapes are michi's `pat3src` (MIT, Petr Baudiš, notice in the source): its first four patterns are hane, the next four cut, the last five edge, expanded as michi's `pat3_expand` does (quarter turn, flips, colour swap, wildcards `?` `x` `o`, space off the board) into one byte per code, a bit per family, built on first use. A code (`pattern3_code`) is the 8 neighbours in row order, two bits each (`NEIGHBOUR_EMPTY`, `_OWN`, `_OPPONENT`, `_OFF_BOARD`), so 65,536 codes; `pattern3_families(code)` looks one up. The families overlap, so one point can have several.
    - `engine/features_test.c` (run by `make test`) pins the tables: 1,536 hane, 13,884 cut, and 1,120 edge codes, overlaps hane∩cut 384, cut∩edge 320, hane∩edge 8, an FNV-1a hash per family computed from michi's own `pat3_expand` (the Python is in the test's comment), and closure under turns, flips, and colour swap. It places concrete shapes in all 8 orientations with either colour and either player to move, in the middle, on edges, and in corners of 5×5, 9×9, and 19×19, and checks refused points (occupied, own eye, suicide, ko recapture; the own-eye exception keeps its features). It checks the tactics on hand-made positions (ko capture, a capture leaving one liberty, saving by capturing away from the chain and by extending, an extension that does not save) and on random games on all three sizes against a reference that plays each move and compares boards, near_last, last_move, and opponent_passed after a stone, a pass, an own move, a suicide, and handicap, the liberty planes, and the layout of all 16 group masks. Its `setup()` clears the last move after placing the stones.
  - `arena SIZE KOMI MAX_MOVES SCHEDULE` (the legacy invocation; `arena.c`, built next to `evo` from `brown.o`, `features.o`, `generate_move.o`, `score.o`, without the GTP code) plays network-against-network games in one process and scores them with `tromp_taylor_score`. SCHEDULE lines are `ID BLACK.ann WHITE.ann`, separated by blanks, so no field holds whitespace; IDs must be distinct, and the whole schedule is checked before the first game. Each distinct path is loaded once. It sets Brown's `komi` as twogtp's `komi` command does, so the network sees the same komi input as through GTP. Stdout: per game, in schedule order and flushed, `ID result=… end=passes|limit length=N time_black=S time_white=S duration=S moves=C3,pass,… ok` (tab-separated, GTP vertices, times monotonic seconds with six decimals), or `ID error=black|white|both message=… ok` without a game when a network is missing, unreadable, or does not fit; then `done N`. Bad arguments (size outside 2–23, komi not a finite number, MAX_MOVES not a whole number 0–10⁹) or a bad schedule: message on stderr, exit 1, nothing on stdout.
    - A game ends where twogtp ends one: after two passes in a row, or after MAX_MOVES + 1 moves (twogtp refuses a genmove only once more than `-maxmoves` moves were played, so `-maxmoves 10` gives LEN 11); passes count as moves, and two passes on the last allowed move end it by passes. Rules are Brown's (simple ko, no superko; a cycle ends at the move limit). The legacy invocation has no time limit.
    - `arena --mixed SIZE KOMI MAX_MOVES MAIN_TIME RESPONSE_DEADLINE GRACE MANIFEST` is the opt-in invocation for games with external GTP programs (bots); nothing uses it yet, and `arena --protocol` prints its protocol version, `3`, and exits 0. The times are decimal seconds (`600`, `0.05`; at most 10⁶): MAIN_TIME is each side's absolute main time per game (above 0), RESPONSE_DEADLINE bounds a bot's answer to setup, `play` and `quit` (above 0), GRACE is how long past its remaining main time a bot's `genmove` answer is waited for (0 or more). MANIFEST lines are a kind and fields separated by single tabs (no empty field, no control character, no blank line): players first, `network PLAYER PATH` or `bot PLAYER`, then games, `game GAME BLACK WHITE`, and for every bot side of every game exactly one `command GAME black|white COMMAND` after its game line, the whole command in the stored opponent format, per game so it carries GNU Go's `--seed`. IDs are printable ASCII without spaces and distinct (players among players, games among games); a player may play both colors or not at all. Only COMMAND is ever split at whitespace, into an argv as twogtp's `StringUtil.splitArguments` does. Stdout: the header `arena protocol 3 ready` once arguments and manifest are checked, before any network loads; per game, in manifest order, flushed, tab-separated and ending in `ok`, either `GAME result=R end=passes|limit|resign|time length=N time_black=S time_white=S duration=S moves=M ok` (the legacy line; R is the Tromp–Taylor score, `B+R`/`W+R` when the other side's bot resigned, `B+T`/`W+T` when the other side's network overran main time, the overrunning move included), `GAME end=network_error error=black|white message=TEXT ok` (that network loses without a move), or a failure record, `GAME end=network_error error=both message=TEXT ok` or `GAME end=timeout|illegal|crash|launch error=black|white length=N time_black=S time_white=S duration=S moves=M message=TEXT ok` with the moves and times before the failure (`error` is the failing bot's color; `launch` covers any failure before the bot's first `play` or `genmove`); then `done N` when every game has a record. Moves are lowercase `pass` and uppercase coordinates, empty for none. Exit 0 after the trailer; 2 right after a failure record, with no later game and no trailer; 1 with a message on stderr for bad arguments, a bad manifest (before the header), or a failed write; never 130 or 143, which the runner reads as an interrupt. Stored end reasons are `passes`, `limit`, `resign`, `time` and one-sided `network_error`; the failure records are output-only. `engine/arena.c`'s header comment has the full definitions. For now a manifest whose games include a bot is refused (exit 1, before the header) as not supported yet, the times use `CLOCK_MONOTONIC`, and there is no main-time check.
    - `scripts/arena-agreement.sh` (run by `mise run smoke`, so by CI's `smoke-matches`) plays 152 games between seeded random networks (every ordered pairing of 5 networks on 9×9 with max_moves 120 and of 8 on 5×5 with 40, once without feature groups and once with all, from `initial-population`'s `all` with noise 0.3) in the arena and through `gogui-twogtp` with evo and the `--chinese-rules` GNU Go referee (seed 1), at komi 6.5. It fails if a game's moves, length, or end differ, if the arena's result differs from its own Tromp–Taylor count of twogtp's final position (from GNU Go's `loadsgf` and `list_stones`), if on a two-pass game where GNU Go's `final_status_list dead` is empty the winner differs from the referee's, if fewer than 5 games reach that comparison (the sample gives 24: 10 without features, 14 with), or on a twogtp error other than the move limit or a missing referee result. Winner differences on games with dead stones or at the move limit are expected (Tromp–Taylor keeps dead stones) and only counted. The counts depend on the networks' moves, which `-march=native` can change between machines; if a machine falls below the minimum, enlarge the sample rather than lower it. It takes about 26 s with 4 twogtp games at a time. The file is not executable; run it with `sh`, as `mise run smoke` does.
    - `arenatest.sh` (`make arenatest`, run by the root `make test` after `initial-population` is built) uses hand-made networks without hidden layers whose moves follow from the rules alone, so it pins moves on every machine: among them tactics networks whose network weights are all 0 (every point 0, pass −1), so only their feature weights change a move (capture 1: it captures; self_atari −10: it skips a self-atari; all 0: it plays like `play.ann`). It compares seeded random networks, without groups and with all, with evo's GTP moves instead of pinning theirs (`-march=native` floating point may differ between machines). It also checks `--protocol`, that `--mixed` gives the header, the legacy line for each played game, the `network_error` records, and the stop after `error=both`, and that it refuses bad times and each kind of malformed manifest before the header.
- `initial-population/`: `initial-population POP SIZE LAYERS NEURONS COPY_CHANCE WEIGHT_CHANGES WEIGHT_STEP ACTIVATION_RATE STRUCTURE_RATE GROUPS NOISE FEATURE_STEP [SEED]` writes random networks named `0001.ann`, `0002.ann`, and so on, each with the genes given, and prints one line per network, in file order: `genes layers=L width=W act_hidden=NAME act_output=NAME copy_chance=G weight_changes=G weight_step=G activation_rate=G structure_rate=G features=GROUPS feature_step=G` and then `fw_NAME=G` for each move feature of the groups, in `ANN_FEATURES`' order (`%.17g`; width 0 without hidden layers; GROUPS is the groups comma-separated in `ANN_GROUP_NAMES`' order, `shapes,tactics,last_move,liberties`, or `none`, never `all`; `liberties` has no move feature, so `features=none` and `features=liberties` lines end at `feature_step`). GROUPS is `none`, `all`, or distinct group names separated by commas, in any order; the networks have those groups' inputs (`ann_layout_inputs`, 974 on 9×9 with `all`) and feature weights, each weight its starting value in `ANN_FEATURES` times 1 + u, u uniform within ±NOISE (0–1), drawn per network after its own weights from the same stream, in feature order (even when NOISE is 0; without move features nothing is drawn, so `none` gives the same networks as before features existed), and `feature_step` FEATURE_STEP. It exits 1 on a board size outside 2–23, on bad GROUPS, on NOISE or FEATURE_STEP out of range or not a finite number, and on a gene that is not a finite number or lies outside its range for the network's size. The runner passes the experiment's `initial_*` settings (see Running experiments), then its `features`, `initial_feature_noise`, and `initial_feature_step` settings as GROUPS, NOISE, and FEATURE_STEP, and stores each line in the network's `births` row, matching lines to files in order and refusing a run whose lines are missing, malformed (`parse_genes` in `ruby/run_generation.rb` checks the feature weights against the groups with `ruby/feature_groups.rb`, which mirrors the C tables), of another shape, or of another feature set than the experiment's (`RunGeneration#experiment_features`, the `features` setting, stored in the genes line's form).
- `evolve/`: `evolve RATE META_RATE MAX_LAYERS MAX_WIDTH ADD_WIDTH A.ann B.ann OUT.ann [SEED]` writes the child to `OUT.ann`. RATE is the crossover rate (0–1), META_RATE the τ of self-adaptive mutation (a finite number ≥ 0); MAX_LAYERS (≥ 0), MAX_WIDTH (≥ 1), and ADD_WIDTH (1 to MAX_WIDTH) bound the child's shape and give the width of a layer added to a network without hidden layers. Every number is parsed strictly (like the seed), and a bad one exits 1 with a message. The runner passes the `meta_rate` setting, the `max_hidden_layers` and `max_layer_size` settings as MAX_LAYERS and MAX_WIDTH, and min(`layer_size`, `max_layer_size`) as ADD_WIDTH, and stores both lines in the child's `births` row; a missing or malformed line, or a genes line of another feature set than the experiment's, stops breeding. Its last two stdout lines are `summary operator=crossover|mutation|copy parent=first|second structure=none|widen|narrow|add_layer|remove_layer activation_changed=0|1 differs_from_first=N differs_from_second=N` (`parent` is the picked parent in argument order; differs counts the network weights differing from each parent, not the feature weights, so 0 means the same network weights (an identical copy, or a mutation that changed only its genes and feature weights), and -1, which the runner stores as NULL, means the child's shape differs from that parent's) and the child's genes line, in `initial-population`'s format (`ann_print_genes_line` in `lib/ann.h`). A child comes about by one of three operators, never more than one: crossover, mutation, or copy. Crossover needs parents of the same shape (inputs, outputs, hidden layers, and width, which does not count without hidden layers); for parents of different shapes the child is a mutation of the picked parent instead (`breed()` in `evolve/evolve.c`; the operator is drawn either way). A crossover child takes the activations, genes, and features (feature weights and `feature_step`) of the parent whose weights come first and is not mutated. A mutation (`mutate()` in `evolve/evolve.c`) is driven by the mutated parent's genes and is self-adaptive: with the parent's `copy_chance` the child is an exact copy, genes, features, and activations included (`operator=copy`); otherwise the genes mutate first (`weight_changes` and `weight_step` log-normally, `g·exp(τ·N(0,1))`, the three probabilities on the logit scale, then clamped to their ranges), then the features (`mutate_features`), only when the groups have move features: `feature_step` log-normally with the same τ, clamped to [1e-4, 1], and then every feature weight by a uniform amount within ±the new `feature_step`, clamped to [−10, 10] (without groups, or with only `liberties`, nothing is drawn and the features stay as they are, so such a network's child is the one the build before feature breeding gave for the same seed), and the new genes drive the rest: with `activation_rate` each of the two activations independently switches to one of the other five in `ANN_ACTIVATIONS`, chosen uniformly; then with `structure_rate` the child undergoes one structural change, chosen uniformly among those the bounds allow (below); and then each weight changes with probability `weight_changes / total_weights` by a uniform amount within `±weight_step`, with `weight_changes` clamped to the child's final `total_weights`. Threshold and relu outputs often tie, and the engine passes on a tie, so networks with them pass a lot; a pass-heavy run is selection at work, not a bug. N(0,1) comes from Box–Muller on PCG with no cached spare, and the draws come in a fixed order (operator, parent, copy check, the genes in `ann_genes` order, `feature_step` and then the feature weights in `ANN_FEATURES`' order, the hidden and then the output activation, each a switch draw followed by a choice draw only when it switches, the structure draw and then the change's choice, its neuron indices (narrow, one per layer in order), and its random weights (in weight order; building the reshaped network itself draws nothing), the weights), so a seed gives one child. When the bounds allow no change, there is no structure draw at all. Parents may differ in shape, activations, genes, and feature weights, and structural changes work for any input count (a fold from one hidden layer lands on every input, the feature inputs included). It exits 1 without writing anything when an input cannot be read, when the parents differ in inputs or outputs or in feature groups (compared as masks: `shapes` and `liberties` add as many inputs; one experiment has one feature set, so this is a broken setup), or when the child cannot be written. The runner checks the exit status and that the file exists, and stops breeding before deleting the parents if either fails.
  - The owner-facing explanations are `docs/genes.md` and, for the features, `docs/features.md`; keep them in step with changes to genes, features, `evolve`, or `stats`.
  - Structural changes (`widen`, `narrow`, `add_layer`, `remove_layer` in `evolve/evolve.h`), allowed within width 1..MAX_WIDTH and layers 0..MAX_LAYERS (widen and narrow need hidden layers). In GENANN's layout each neuron's row is its bias (the weight of a constant −1 input) and then one weight per neuron of the layer before. **Widen** appends a neuron to every hidden layer, with random incoming weights in GENANN's initial range [−0.5, 0.5) and weight 0 into the next layer's existing neurons and the outputs, so the outputs stay the same up to rounding (with clang they are `==` equal; GCC vectorizes GENANN's sums, so a longer row can round differently in the last bit). **Narrow** removes from every hidden layer a neuron drawn independently per layer, with its row and its column. **add_layer** inserts a pass-through layer after the last hidden one (bias 0, weight 1 from the neuron at the same position): exact for linear, relu, and threshold, close for tanh (about 180/200 same moves); for sigmoid and sigmoid_cached the output rows are compensated by sigmoid(x) ≈ 0.5 + x/4 (V′ = 4V, B′ = B + 2ΣV). From no hidden layers the new layer has ADD_WIDTH neurons and random weights, and so do the output rows. **remove_layer** folds the last hidden layer into the output rows, taking its activation as a straight line c + s·x (linear, relu, tanh: c = 0, s = 1; sigmoid, sigmoid_cached, threshold: c = 0.5, s = 1/4): new weight s·Σ_k V[o][k]·W[k][j], new bias B_o − Σ_k V[o][k]·(c − s·b_k); from one hidden layer the outputs fold onto every input, komi included. A linear fold agrees to about 1e-15 (sums reassociate); add then remove gives the parent back byte for byte for linear, relu, and tanh, and up to rounding for the sigmoids. Folds of the other activations are rough, so a drop in play after a removal is expected, not a bug.
  - `evolve/test.c` (`make test` in `evolve/`) pins the gene-driven mutation statistically: with fixed genes away from their clamps it mutates seeded networks thousands of times and checks the share of copies against `copy_chance`, the changed weights per child against `weight_changes` (with τ 0, so the genes stay put, and with τ 0.5 against each child's own mutated gene), the changes as uniform within `±weight_step`, and each gene's step (log ratio or logit difference) as N(0, τ) and independent of the others, all against tolerances of about four standard errors; the same for the features: every feature weight of a mutated child changes, uniformly within `±feature_step` (τ 0), and `feature_step`'s log ratio is part of the N(0, τ) and independence check, which runs through `mutate()` itself; the feature draws come right after the genes' and, replayed by hand from the raw generator at τ 0.5, are `feature_step`'s normal and then one uniform per weight scaled by the new step, a copy keeps the features, a crossover child takes the picked parent's, a network without move features draws nothing for them, and parents of different groups with equal input counts cannot breed; it also checks the clamps at extreme genes and feature values, that a seed gives a byte-identical child, that activations switch with `activation_rate` (with τ 0), never to the same one and uniformly to the other five, and that copies and crossover children never switch; and the structural operators: widen keeps the outputs (within a relative 1e-12, same argmax) for all six activations and 1–3 layers, add_layer for linear, relu, and threshold, a linear fold agrees to a relative 1e-9 and picks the same move, add then remove round-trips, narrow removes uniformly and independently per layer, the change is drawn with `structure_rate` and uniformly among the allowed ones, the bounds hold, no structure is drawn when none is allowed, the operators draw only their own numbers, and parents of different shapes never cross over. Changing how mutation works means updating those tests. The statistical checks do not depend on the exact random draws; only the copy and seed tests rely on a particular seed. `make evolvetest` relies on particular seeds (for example seed 28 draws a copy, seed 8 switches both activations, and seed 3 adds a layer). Its parents without groups differ in `feature_step`, and it checks that a crossover child's first 86 bytes (header, genes, and features) and a mutated child's feature block are the picked parent's. Parents with every group check that a crossover child's first 142 bytes are the picked parent's, a copy is byte-identical, a mutation (seed 3, which changes no network weight: differs 0) keeps the mask and changes `feature_step` and all 7 feature weights, and its genes line equals the one a crossover of the child with itself reads back from its file, a `remove_layer` from one hidden layer (seed 28) plays, and `shapes` and `liberties` parents (both 325 inputs on 9×9) exit 1.
- `ruby/`, `runner`: tournament orchestration, and the benchmark (`ruby/checkpoint_benchmark.rb`, openings in `ruby/openings.rb`). `ruby/arena_result.rb` parses one arena run's stdout strictly: `ArenaResult.chunk(text, ids)` gives every scheduled ID a result with `GameResult`'s interface plus `duration` and `moves` (a line that does not match exactly, a missing line, or two lines for one ID give the failure `arena: no result`; lines for unscheduled IDs are ignored), and `complete?` is true only with a matching `done N` trailer. `ArenaResult#sgf` builds the SGF from the moves; `test/fixtures/arena/` pairs arena lines with the move nodes of twogtp SGFs of the same games. `stats` (figures in `ruby/experiment_stats.rb`, output in `ruby/stats_report.rb`), `ranking`: viewers.
- `lib/`: the network code every program links, built once as `lib/libann.a`. `genann.c` and `genann.h` are upstream GENANN v1.1.1, unchanged (license in `lib/GENANN-LICENSE`); to update GENANN, copy the new upstream files over them. Evo's additions live in `ann.h` and `ann.c`: the PCG `GENANN_RANDOM`, the genes (`ann_genes`, their ranges, `ann_default_genes`, `ann_genes_invalid`, and the genes line `ann_print_genes_line`), the features (`ann_features`, `ANN_FEATURES` with each move feature's group and starting weight, the clamps, `ann_default_features`, `ann_features_invalid`, and the board sides `ANN_MIN_SIDE`/`ANN_MAX_SIDE`), the feature groups, their names in fixed order, and the input layout's counts (`ANN_GROUP_*`, `ANN_GROUP_NAMES`, `ann_feature_count`, `ann_layout_inputs`; see `features.c` under `engine/`), and `ann_binary_read`/`ann_binary_write` for the `.ann` format with the activation table. Programs include `ann.h`, never `genann.h`. `lib/test.c` (`make test` in `lib/`) tests GENANN and the `.ann` round trip. `lib/minctest.h` is the test framework for `lib/` and `evolve/`.
- `pcg-c/` is an upstream submodule (`imneme/pcg-c`). Do not edit it.

## Engine and network files

- `evo NETWORK.ann` starts at board size 6, so send `boardsize` before `genmove`. Without exactly one file argument it prints a usage message and exits 1; a file that is missing or holds no network makes it exit 1 at startup with a message naming it.
- `boardsize` answers `? unacceptable size` for a size the loaded network does not fit, and `genmove` answers `? network does not fit the board` if no fitting `boardsize` came first. The process keeps running. `engine/enginetest.sh` (`make test`) checks a whole GTP session, and `engine/gtp_test.c` (`make test`) what evo's GTP commands leave in Brown's state, and that `place_free_handicap` plays the network with its features.
- The engine answers `name` with `Evo`.
- The `.ann` format (`lib/ann.h`), version 2, holds everything a GENANN network is, plus its genes and its features: the magic `EVOANN`, the format version (2), the sizes inputs, hidden_layers, hidden (always 0 without hidden layers: normalized on write, required on read), and outputs, a code for the hidden and the output activation (every activation GENANN offers has one, in `ANN_ACTIVATIONS`), the genes (`ann_genes`: `copy_chance`, `weight_changes`, `weight_step`, `activation_rate`, `structure_rate`) as doubles, then the features (`ann_features`): a uint32 mask of feature groups (`ANN_GROUP_*`, 0 for none), `feature_step` as a double, and one double weight per move feature of the groups (F = `ann_feature_count`, in `ANN_FEATURES`' order), then the weights as doubles: 86 + 8F bytes before the weights. All numbers are little-endian and fixed-size, so files are portable. Reading rejects a wrong magic or any version but 2 (version 1 files, from before the features, are no longer read), an unknown activation, genes that are not finite or lie outside their ranges (`ANN_*_MIN`/`_MAX` in `lib/ann.h`; `weight_changes` runs from 1 to the network's total weights), a mask with a bit that is no group, a `feature_step` outside [1e-4, 1] or a feature weight outside [−10, 10] (or not finite), outputs that are not a square board of `ANN_MIN_SIDE` to `ANN_MAX_SIDE` points a side plus pass (2 to 23, Brown's `MIN_BOARD`/`MAX_BOARD`, which `generate_move.c` checks at compile time), inputs other than `ann_layout_inputs(groups, points)` for that board, and a file that is too short or too long. Writing refuses missing or invalid genes or features, but does not check the shape against a board (`evolve/test.c` writes small networks of other shapes). `ann_binary_read(in, genes, features)` takes NULL for either when the caller does not need it; `ann_binary_write(ann, genes, features, out)` requires both. `ann_default_features(groups)` gives `feature_step` 0.01 and the hand-set starting weights (`ANN_FEATURES`: hane, cut, edge, and near_last +0.05, capture +1.0, saves_atari +0.8, self_atari −1.0). The runner gives every network the experiment's `features` setting (default `all`; see Running experiments); `evolve` breeds the features (see `evolve/`), and `evo` and `arena` play with the features they read (see `genmove`). An experiment created before version 2 keeps its own copied executables, which still read its version-1 networks, but nothing built since does, and such an experiment is not supported.
  - A network for board size N has N²+1 outputs (pass last) and `ann_layout_inputs(groups, N²)` inputs: N²+1 without groups (komi first), 1 + 12·N² + 1 with all (974 on 9×9).
  - `engine/example.ann` is a 9×9 test fixture with 2×2 hidden neurons, cached sigmoid activations, the default genes, no feature groups (the default `feature_step`), and 418 weights. It is not a trained player.
- Move choice takes the highest score: the network's output plus its feature weights (B), as the `genmove` bullet says. It is deterministic for a given network and position.
  - `initial-population` and `evolve` take an optional seed as their last argument; the same seed gives byte-identical output. Without one they seed from `time(NULL)` plus an address.
- Runs are reproducible from the experiment seed (the `seed` setting; `SetupExperiment` generates and saves one if it is missing). `ruby/seeds.rb` derives every other seed from it and a label: the initial population, each child (`birth`, generation, index), parent selection, tie order and colors per round, a per-game GNU Go `--seed` for the referee and GNU Go players (`Seeds.gnugo`, added to a command by `Seeds.with_gnugo_seed`), in the tournament and in the benchmark, and the benchmark openings. Two runs with the same seed, even with parallel games, produce the same networks, pairings, moves, rankings, and benchmark results; only the date in the SGF headers differs. Losing a game on time would still differ.
- Besides `games`, the experiment database records `births` (each network's parents, operator, differing weights, seed, and SHA-256 of its `.ann`, and from migration 010 the picked `parent`, `structure`, `activation_changed`, and its genes line as `layers`, `width`, `act_hidden`, `act_output`, `copy_chance`, `weight_changes`, `weight_step`, `activation_rate`, `structure_rate`, and from migration 011 `features` (the genes line's form), `feature_step`, and one column per feature weight, `fw_hane`, `fw_cut`, `fw_edge`, `fw_capture`, `fw_self_atari`, `fw_saves_atari`, `fw_near_last` (`ExperimentDatabase::BIRTH_FEATURE_WEIGHT_COLUMNS`), NULL when the network's groups lack that feature; generation 0 has operator `initial`, genes, and no parent, structure, or activation_changed; a differs count is NULL for a parent of another shape, so readers such as `ExperimentStats` handle NULL) and `rankings` (each generation's standings, kept current after every game; final once the generation is done).
- Brown's own `final_score` is unreliable on arbitrary positions: an empty 9×9 board scores `W+87.5`. Use the arena's `tromp_taylor_score` or the referee's result.
- The build uses `-march=native`. Binaries are for the local machine only.
- macOS ships GNU make 3.81, which compares timestamps to the second. A C file edited and rebuilt within the same second can leave the old object in place, so a quick edit-rebuild-test loop (such as checking that a test catches a mutant) may run a stale binary. Delete the `.o` files before rebuilding in that case.
- macOS `cmp -n N A B SKIP1 SKIP2` misreports EOF when the bytes left after the two skips differ in length, even though `-n` limits the range. To compare byte ranges at different offsets, dump them with `od` and compare the dumps.

## Build and test notes

- Build from the repository root. The subdirectory Makefiles link `../pcg-c/src/libpcg_random.a` and `../lib/libann.a`, and fail if `make pcg` and `make lib` have not run.
- `mise run example` opens the GoGui window. Do not use it headless. `gogui-twogtp` runs without a display.
- Ruby tests live in `test/` (minitest). They build `RunGeneration` with `allocate` and set its instance variables directly (settings, a seeded `rng`, a fake pool), and they stub `../evolve` by overriding `run_evolve` on that object (and `initial-population` by overriding `system`). The PR script tests run `scripts/pr-checks.sh` against a fake `gh` on `PATH` (`test/fake_gh.rb`). `PR_CHECKS_TRIES` and `PR_CHECKS_SLEEP` shorten the wait for checks to register. There is no Ruby linter yet.
- `ExperimentDatabase#save_state` and `RunGeneration#save_data` take a keyword argument besides the state hash (the test helper `write_data` accepts either form). In Ruby 3 a brace-less hash argument such as `save_state(1, 'round' => 0)` is then taken as keywords and fails with a wrong-number-of-arguments error, so pass the state in braces: `save_state(1, { 'round' => 0 })`.

## CI and external tools

- CI (`.github/workflows/ci.yml`) runs on every pull request, whatever its base (so stacked PRs get checks), and on pushes to `main`, on Ubuntu, with one job per kind of check: `c-tests` (`test-c`), `ruby-tests` (`test-ruby`), and `smoke-matches` (`setup-experiments`, `doctor`, `smoke`). Branch protection on `main` requires these jobs by name, so renaming or adding a job also needs the protection rule updated. CI caches the gems (keyed on `Gemfile.lock` and `mise.toml`) and the built external tools in `.local/evo-tools` (keyed on the installer, the manifest, and `scripts/patches/`). Both keys also include the runner image, because the caches hold compiled code. A change to how the tools build has to change one of those files, or CI keeps using the old build. Bumping `release_id` does that. Local setup is usually macOS with Apple clang, so code that builds GNU Go or other external tools has to work with both clang and GCC. A green local `verify` says nothing about Linux; wait for CI. Docker reproduces CI's toolchain locally when a change needs checking before that: `gcc:14` for the C build, `ubuntu:24.04` for its `mawk` and `dash`. A `gcc:14` build that fails with `brown.dep: Directory nonexistent` is a flake; run it once more. Copy `pcg-c` into the image as plain files: its `.git` points back to the checkout it came from, so a `git clean` inside the copy deletes that checkout's build output.
