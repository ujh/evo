# CLAUDE.md

Evo evolves dense neural networks that play Go: their weights, activations, mutation settings, and shape. The C programs build, breed, and play networks. The Ruby scripts run the tournaments: games between two networks in the C arena, scored by Tromp–Taylor, and games with a bot through GoGui, with GNU Go as referee. The goal is a network that plays Go well, reached through evolution: evolution should show measurable improvement, and any head start is welcome, such as Go knowledge given to the network as extra inputs, or search. Improvement need not come from evolution alone, so compare a head start against a run without it rather than ruling it out.

`PROJECT_NOTES.md` holds only work still to do: known defects, cleanup, proposed experiments, and open questions. Read it before changing behavior. When a change fixes a listed item or settles a question, delete it from `PROJECT_NOTES.md` in the same change. Do not record finished work or history there. If a future agent must know something about the change, put it in this file instead.

## Commands

Always go through mise. It pins Ruby 4.0, Java 21, and jq, and it puts `.local/evo-tools/current/bin` (GNU Go, Brown, AmiGoGtp, GoGui) on `PATH`. A bare shell has none of these. For one-off commands, use `mise exec -- <cmd>`.

| Task | Command |
| --- | --- |
| First setup (submodule, gems, build) | `mise run setup` |
| Install external Go programs | `mise run setup-experiments` (downloads from the project's own GitHub release with pinned checksums, and builds under `.local/evo-tools/`) |
| Build | `mise run build` (root `make`; builds `pcg-c` first) |
| Tests (C and Ruby) | `mise run test` (or `test-c`, `test-ruby` alone) |
| Full check, same as CI | `mise run verify` (tests, `doctor`, and `smoke`: refereed GoGui matches with every bot and Evo, and the arena agreement check) |
| Create an experiment without prompts | `mise run new-experiment NAME --board-size 9 ...` (without arguments it lists the options) |
| Run/resume experiment | `mise run run NAME [CONCURRENCY [one-generation]]` |

- Build from the repository root. The subdirectory Makefiles link `../pcg-c/src/libpcg_random.a` and `../lib/libann.a`, and fail if `make pcg` and `make lib` have not run.
- `mise run example` opens the GoGui window. Do not use it headless. `gogui-twogtp` runs without a display.
- Ruby tests live in `test/` (minitest). They build `RunGeneration` with `allocate` and set its instance variables directly (settings, a seeded `rng`, a fake pool), and they stub `../evolve` by overriding `run_evolve` on that object (and `initial-population` by overriding `system`). The PR script tests run `scripts/pr-checks.sh` against a fake `gh` on `PATH` (`test/fake_gh.rb`). `PR_CHECKS_TRIES` and `PR_CHECKS_SLEEP` shorten the wait for checks to register. There is no Ruby linter yet.
- `ExperimentDatabase#save_state` and `RunGeneration#save_data` take a keyword argument besides the state hash (the test helper `write_data` accepts either form). In Ruby 3 a brace-less hash argument such as `save_state(1, 'round' => 0)` is then taken as keywords and fails with a wrong-number-of-arguments error, so pass the state in braces: `save_state(1, { 'round' => 0 })`.

## Layout

- `engine/`: `evo`, a GTP engine built on Brown's board code (`brown.c`, `gtp.c`) plus the network move policy (`generate_move.c`). `engine/rules_test.c` (`make test` in `engine/`) pins Brown's rules, the move filter, and the move choice with feature weights, and `enginetest.sh` and `gtp_test.c` check them through GTP `play`:
  - Captures remove every neighboring opponent string left without a liberty. Ko is simple ko: only an immediate single-stone recapture is refused, and any other move or a pass ends it.
  - `legal_move` and GTP `play` accept suicide; the suicided string is removed at once.
  - `genmove` scores each point as the network's output plus B, the network's feature weights: for each move feature of its groups that is 1 at the point, that feature's weight (`ann_features.weights`, in `ANN_FEATURES`' order); the pass output gets nothing. Without groups the scores are the outputs. It then plays the highest-scoring point that is legal, not suicide, and not the opponent's suicide point (in effect an own eye) unless it touches an opponent stone: `move_allowed` in `features.c`, which the move features use too. It passes when nothing is allowed or the pass output scores at least as high, so a tie (common with saturated cached sigmoid outputs) passes.
  - `generate_move(ann, features, &i, &j, color)` (`features` NULL means no groups) fills the inputs with `feature_inputs` for the network's groups, runs the network, adds B, and picks with `find_and_set_best_move`, so for a network without groups the moves are those from before the features. `ann_fits_board(ann, features, size)` checks the inputs against `ann_layout_inputs` of the feature set on that board and the outputs against its points plus pass. The input buffer holds `GENERATE_MOVE_MAX_INPUTS`, every group on 23×23 (6,350; `rules_test` checks it against `ann_layout_inputs`). evo (`network_features` in `interface.c`, `place_free_handicap` included) and the arena (each loaded network's `features`) pass the features read with the network. `generate_move.c` takes the network as an argument and owns its input buffer, so `brown.o` + `features.o` + `generate_move.o` + `lib/libann.a` link without the GTP code (`gtp.o`, `interface.o`). `rules_test` links that way, which keeps it so, and checks that the move choice refuses exactly the points `move_allowed` refuses. `ann` stays a global of `interface.c` for evo's GTP commands. Start a game with `new_game()`, which also clears Brown's ko point (GTP `clear_board` and `init_brown` use it); `clear_board()` empties the board and forgets the last move but keeps the ko point.
  - Brown records the last move: `play_move` (a pass is `play_move(-1, -1, color)` or `play_pass(color)`) stores the point or pass and its colour, and `last_move(&i, &j, &color)` returns `LAST_MOVE_NONE`, `LAST_MOVE_PASS`, or `LAST_MOVE_POINT` (i, j −1 for a pass or none, colour `EMPTY` for none; NULL arguments allowed). A suicide is still the last move, at a point that is empty again. `new_game` and `clear_board` reset it; handicap stones are not moves, so `place_fixed_handicap` (in `brown.c`) and GTP `set_free_handicap` and `place_free_handicap` (in `interface.c`) call `clear_last_move()` after placing them with `play_move`, and `set_free_handicap`'s error paths call `clear_board`. GTP `play`, `genmove` (pass included), and the arena play through `play_move`, so they need nothing else.
  - `brown_save(&s)`/`brown_restore(&s)` copy Brown's whole game state (board, string links `next_stone`, ko point, last move; not `board_size`, `komi`, or the final status) into and out of a caller's `brown_state` (about 4 kB, arrays sized for `MAX_BOARD`). A trial move is save, `play_move`, read, restore; a snapshot can be restored any number of times, and callers may hold several. `rules_test.c` checks that a restore after a trial capture and a trial ko capture gives back the same board, strings, legal moves (the ko), and last move.
  - `features.c` (`features.h`; include `brown.h` first) computes the features from Brown's board for the player to move; it needs only `brown.o` and `lib/libann.a` (the layout's counts), and `features_test` links it so. `generate_move` uses it for every network's inputs and for B.
    - Move features, bits `FEATURE_BIT(f)` in the input layout's order: `FEATURE_HANE`, `_CUT`, `_EDGE` (group shapes), `_CAPTURE`, `_SELF_ATARI`, `_SAVES_ATARI` (tactics), `_NEAR_LAST` (last_move); `MOVE_FEATURES` counts them, and `group_features(groups)` gives a group mask's bits. All are 0 wherever `move_allowed` is false. capture: the move captures (ko captures too); self_atari: it captures nothing and leaves its chain one liberty; saves_atari: an own chain in atari before has two or more liberties after, by extending or by capturing, touching it or not; near_last: one of the 8 points around the opponent's last stone, only when the last move was the opponent's stone and it is still on the board (not after a pass, an own move, a suicide, or handicap stones). `move_features_board(color, wanted, bits)` computes the `wanted` bits of the whole board in one pass; a trial move (undone with `brown_restore`, so the board, ko point, and last move stay) happens only where a tactical feature can be 1 (a capture, a touched own chain in atari, or fewer than two empty neighbours). With every group, `feature_inputs` takes about 5 µs per board on 9×9 and 19 µs on 19×19 (26 Sep 2026). `move_features_at(i, j, color)` computes the whole board for one point, so use it only in tests. `chain_liberties(i, j)` is 0 at an empty point.
    - The group bits (`ANN_GROUP_SHAPES`, `_TACTICS`, `_LAST_MOVE`, `_LIBERTIES`, `ANN_GROUPS_ALL`) and the layout's counts (`ann_feature_count(groups)`, the move features F; `ann_layout_inputs(groups, points)`; both -1 for an unknown bit) live in `lib/ann.h`, since the `.ann` reader needs them. `feature_inputs(groups, color, inputs, bits)` fills `[komi][N stones][F×N move features][3×N liberties][N last_move][opponent_passed]`, only the groups present: liberties has +1 (own) or −1 (opponent) at each stone in the plane for its chain's 1, 2, or 3+ liberties; the last_move plane is 1 at the stone near_last goes by; opponent_passed is 1 after the opponent's pass. Komi and stones come first for every feature set, so `features none` gives the inputs from before the features. It returns the count, and fills `bits` with the groups' move features unless NULL.
    - The shapes are michi's `pat3src` (MIT, Petr Baudiš, notice in the source): its first four patterns are hane, the next four cut, the last five edge, expanded as michi's `pat3_expand` does (quarter turn, flips, colour swap, wildcards `?` `x` `o`, space off the board) into one byte per code, a bit per family, built on first use. A code (`pattern3_code`) is the 8 neighbours in row order, two bits each (`NEIGHBOUR_EMPTY`, `_OWN`, `_OPPONENT`, `_OFF_BOARD`), so 65,536 codes; `pattern3_families(code)` looks one up. The families overlap, so one point can have several.
    - `engine/features_test.c` (run by `make test`) pins the tables: 1,536 hane, 13,884 cut, and 1,120 edge codes, overlaps hane∩cut 384, cut∩edge 320, hane∩edge 8, an FNV-1a hash per family computed from michi's own `pat3_expand` (the Python is in the test's comment), and closure under turns, flips, and colour swap. It places concrete shapes in all 8 orientations with either colour and either player to move, in the middle, on edges, and in corners of 5×5, 9×9, and 19×19, and checks refused points (occupied, own eye, suicide, ko recapture; the own-eye exception keeps its features). It checks the tactics on hand-made positions (ko capture, a capture leaving one liberty, saving by capturing away from the chain and by extending, an extension that does not save) and on random games on all three sizes against a reference that plays each move and compares boards, near_last, last_move, and opponent_passed after a stone, a pass, an own move, a suicide, and handicap, the liberty planes, and the layout of all 16 group masks. Its `setup()` clears the last move after placing the stones.
  - `arena SIZE KOMI MAX_MOVES SCHEDULE` (`arena.c`, built next to `evo` from `brown.o`, `features.o`, `generate_move.o`, `score.o`, without the GTP code) plays network-against-network games in one process and scores them with `tromp_taylor_score`. SCHEDULE lines are `ID BLACK.ann WHITE.ann`, separated by blanks, so no field holds whitespace; IDs must be distinct, and the whole schedule is checked before the first game. Each distinct path is loaded once. It sets Brown's `komi` as twogtp's `komi` command does, so the network sees the same komi input as through GTP. Stdout: per game, in schedule order and flushed, `ID result=… end=passes|limit length=N time_black=S time_white=S duration=S moves=C3,pass,… ok` (tab-separated, GTP vertices, times monotonic seconds with six decimals), or `ID error=black|white|both message=… ok` without a game when a network is missing, unreadable, or does not fit; then `done N`. Bad arguments (size outside 2–23, komi not a finite number, MAX_MOVES not a whole number 0–10⁹) or a bad schedule: message on stderr, exit 1, nothing on stdout.
    - A game ends where twogtp ends one: after two passes in a row, or after MAX_MOVES + 1 moves (twogtp refuses a genmove only once more than `-maxmoves` moves were played, so `-maxmoves 10` gives LEN 11); passes count as moves, and two passes on the last allowed move end it by passes. Rules are Brown's (simple ko, no superko; a cycle ends at the move limit). There is no time limit.
    - `scripts/arena-agreement.sh` (run by `mise run smoke`, so by CI's `smoke-matches`) plays 152 games between seeded random networks (every ordered pairing of 5 networks on 9×9 with max_moves 120 and of 8 on 5×5 with 40, once without feature groups and once with all, from `initial-population`'s `all` with noise 0.3) in the arena and through `gogui-twogtp` with evo and the `--chinese-rules` GNU Go referee (seed 1), at komi 6.5. It fails if a game's moves, length, or end differ, if the arena's result differs from its own Tromp–Taylor count of twogtp's final position (from GNU Go's `loadsgf` and `list_stones`), if on a two-pass game where GNU Go's `final_status_list dead` is empty the winner differs from the referee's, if fewer than 5 games reach that comparison (the sample gives 24: 10 without features, 14 with), or on a twogtp error other than the move limit or a missing referee result. Winner differences on games with dead stones or at the move limit are expected (Tromp–Taylor keeps dead stones) and only counted. The counts depend on the networks' moves, which `-march=native` can change between machines; if a machine falls below the minimum, enlarge the sample rather than lower it. It takes about 26 s with 4 twogtp games at a time.
    - `arenatest.sh` (`make arenatest`, run by the root `make test` after `initial-population` is built) uses hand-made networks without hidden layers whose moves follow from the rules alone, so it pins moves on every machine: among them tactics networks whose network weights are all 0 (every point 0, pass −1), so only their feature weights change a move (capture 1: it captures; self_atari −10: it skips a self-atari; all 0: it plays like `play.ann`). It compares seeded random networks, without groups and with all, with evo's GTP moves instead of pinning theirs (`-march=native` floating point may differ between machines).
- `initial-population/`: `initial-population POP SIZE LAYERS NEURONS COPY_CHANCE WEIGHT_CHANGES WEIGHT_STEP ACTIVATION_RATE STRUCTURE_RATE GROUPS NOISE FEATURE_STEP [SEED]` writes random networks named `0001.ann`, `0002.ann`, and so on, each with the genes given, and prints one line per network, in file order: `genes layers=L width=W act_hidden=NAME act_output=NAME copy_chance=G weight_changes=G weight_step=G activation_rate=G structure_rate=G features=GROUPS feature_step=G` and then `fw_NAME=G` for each move feature of the groups, in `ANN_FEATURES`' order (`%.17g`; width 0 without hidden layers; GROUPS is the groups comma-separated in `ANN_GROUP_NAMES`' order, `shapes,tactics,last_move,liberties`, or `none`, never `all`; `liberties` has no move feature, so `features=none` and `features=liberties` lines end at `feature_step`). GROUPS is `none`, `all`, or distinct group names separated by commas, in any order; the networks have those groups' inputs (`ann_layout_inputs`, 974 on 9×9 with `all`) and feature weights, each weight its starting value in `ANN_FEATURES` times 1 + u, u uniform within ±NOISE (0–1), drawn per network after its own weights from the same stream, in feature order (even when NOISE is 0; without move features nothing is drawn, so `none` gives the same networks as before features existed), and `feature_step` FEATURE_STEP. It exits 1 on a board size outside 2–23, on bad GROUPS, on NOISE or FEATURE_STEP out of range or not a finite number, and on a gene that is not a finite number or lies outside its range for the network's size. The runner passes the experiment's `initial_*` settings (see Running experiments), then `none 0.3 0.01` as literals (`RunGeneration::INITIAL_FEATURE_NOISE` and `INITIAL_FEATURE_STEP`) until it gets feature settings, and stores each line in the network's `births` row, matching lines to files in order and refusing a run whose lines are missing, malformed (`parse_genes` in `ruby/run_generation.rb` checks the feature weights against the groups with `ruby/feature_groups.rb`, which mirrors the C tables), of another shape, or of another feature set than the experiment's (`RunGeneration#experiment_features`, `none` until the runner gets a `features` setting). The feature fields are parsed but not yet stored in `births`.
- `evolve/`: `evolve RATE META_RATE MAX_LAYERS MAX_WIDTH ADD_WIDTH A.ann B.ann OUT.ann [SEED]` writes the child to `OUT.ann`. RATE is the crossover rate (0–1), META_RATE the τ of self-adaptive mutation (a finite number ≥ 0); MAX_LAYERS (≥ 0), MAX_WIDTH (≥ 1), and ADD_WIDTH (1 to MAX_WIDTH) bound the child's shape and give the width of a layer added to a network without hidden layers. Every number is parsed strictly (like the seed), and a bad one exits 1 with a message. The runner passes the `meta_rate` setting, the `max_hidden_layers` and `max_layer_size` settings as MAX_LAYERS and MAX_WIDTH, and min(`layer_size`, `max_layer_size`) as ADD_WIDTH, and stores both lines in the child's `births` row; a missing or malformed line, or a genes line of another feature set than the experiment's, stops breeding. Its last two stdout lines are `summary operator=crossover|mutation|copy parent=first|second structure=none|widen|narrow|add_layer|remove_layer activation_changed=0|1 differs_from_first=N differs_from_second=N` (`parent` is the picked parent in argument order; differs counts the weights differing from each parent, 0 means an identical copy, and -1, which the runner stores as NULL, means the child's shape differs from that parent's) and the child's genes line, in `initial-population`'s format (`ann_print_genes_line` in `lib/ann.h`). A child comes about by one of three operators, never more than one: crossover, mutation, or copy. Crossover needs parents of the same shape (inputs, outputs, hidden layers, and width, which does not count without hidden layers); for parents of different shapes the child is a mutation of the picked parent instead (`breed()` in `evolve/evolve.c`; the operator is drawn either way). A crossover child takes the activations and genes of the parent whose weights come first and is not mutated. A mutation (`mutate()` in `evolve/evolve.c`) is driven by the mutated parent's genes and is self-adaptive: with the parent's `copy_chance` the child is an exact copy, genes and activations included (`operator=copy`); otherwise the genes mutate first (`weight_changes` and `weight_step` log-normally, `g·exp(τ·N(0,1))`, the three probabilities on the logit scale, then clamped to their ranges), and the new genes drive the rest: with `activation_rate` each of the two activations independently switches to one of the other five in `ANN_ACTIVATIONS`, chosen uniformly; then with `structure_rate` the child undergoes one structural change, chosen uniformly among those the bounds allow (below); and then each weight changes with probability `weight_changes / total_weights` by a uniform amount within `±weight_step`, with `weight_changes` clamped to the child's final `total_weights`. Threshold and relu outputs often tie, and the engine passes on a tie, so networks with them pass a lot; a pass-heavy run is selection at work, not a bug. N(0,1) comes from Box–Muller on PCG with no cached spare, and the draws come in a fixed order (operator, parent, copy check, the genes in `ann_genes` order, the hidden and then the output activation, each a switch draw followed by a choice draw only when it switches, the structure draw and then the change's choice, its neuron indices (narrow, one per layer in order), and its random weights (in weight order; building the reshaped network itself draws nothing), the weights), so a seed gives one child. When the bounds allow no change, there is no structure draw at all. Parents may differ in shape, activations, and genes. It exits 1 without writing anything when an input cannot be read, when the parents differ in inputs or outputs, or when the child cannot be written. The runner checks the exit status and that the file exists, and stops breeding before deleting the parents if either fails.
  - The owner-facing explanation is `docs/genes.md`; keep it in step with changes to genes, `evolve`, or `stats`.
  - Structural changes (`widen`, `narrow`, `add_layer`, `remove_layer` in `evolve/evolve.h`), allowed within width 1..MAX_WIDTH and layers 0..MAX_LAYERS (widen and narrow need hidden layers). In GENANN's layout each neuron's row is its bias (the weight of a constant −1 input) and then one weight per neuron of the layer before. **Widen** appends a neuron to every hidden layer, with random incoming weights in GENANN's initial range [−0.5, 0.5) and weight 0 into the next layer's existing neurons and the outputs, so the outputs stay the same up to rounding (with clang they are `==` equal; GCC vectorizes GENANN's sums, so a longer row can round differently in the last bit). **Narrow** removes from every hidden layer a neuron drawn independently per layer, with its row and its column. **add_layer** inserts a pass-through layer after the last hidden one (bias 0, weight 1 from the neuron at the same position): exact for linear, relu, and threshold, close for tanh (about 180/200 same moves); for sigmoid and sigmoid_cached the output rows are compensated by sigmoid(x) ≈ 0.5 + x/4 (V′ = 4V, B′ = B + 2ΣV). From no hidden layers the new layer has ADD_WIDTH neurons and random weights, and so do the output rows. **remove_layer** folds the last hidden layer into the output rows, taking its activation as a straight line c + s·x (linear, relu, tanh: c = 0, s = 1; sigmoid, sigmoid_cached, threshold: c = 0.5, s = 1/4): new weight s·Σ_k V[o][k]·W[k][j], new bias B_o − Σ_k V[o][k]·(c − s·b_k); from one hidden layer the outputs fold onto every input, komi included. A linear fold agrees to about 1e-15 (sums reassociate); add then remove gives the parent back byte for byte for linear, relu, and tanh, and up to rounding for the sigmoids. Folds of the other activations are rough, so a drop in play after a removal is expected, not a bug.
  - `evolve/test.c` (`make test` in `evolve/`) pins the gene-driven mutation statistically: with fixed genes away from their clamps it mutates seeded networks thousands of times and checks the share of copies against `copy_chance`, the changed weights per child against `weight_changes` (with τ 0, so the genes stay put, and with τ 0.5 against each child's own mutated gene), the changes as uniform within `±weight_step`, and each gene's step (log ratio or logit difference) as N(0, τ) and independent of the others, all against tolerances of about four standard errors; it also checks the clamps at extreme genes, that a seed gives a byte-identical child, that activations switch with `activation_rate` (with τ 0), never to the same one and uniformly to the other five, and that copies and crossover children never switch; and the structural operators: widen keeps the outputs (within a relative 1e-12, same argmax) for all six activations and 1–3 layers, add_layer for linear, relu, and threshold, a linear fold agrees to a relative 1e-9 and picks the same move, add then remove round-trips, narrow removes uniformly and independently per layer, the change is drawn with `structure_rate` and uniformly among the allowed ones, the bounds hold, no structure is drawn when none is allowed, the operators draw only their own numbers, and parents of different shapes never cross over. Changing how mutation works means updating those tests. The statistical checks do not depend on the exact random draws; only the copy and seed tests rely on a particular seed. `make evolvetest` relies on particular seeds (for example seed 28 draws a copy, seed 8 switches both activations, and seed 3 adds a layer). Its parents differ in `feature_step` (it patches the second's), and it checks that a crossover child's first 86 + 8F bytes (header, genes, and features) and a mutated child's feature block are the picked parent's.
- `ruby/`, `runner`: tournament orchestration, and the benchmark (`ruby/checkpoint_benchmark.rb`, openings in `ruby/openings.rb`). `ruby/arena_result.rb` parses one arena run's stdout strictly: `ArenaResult.chunk(text, ids)` gives every scheduled ID a result with `GameResult`'s interface plus `duration` and `moves` (a line that does not match exactly, a missing line, or two lines for one ID give the failure `arena: no result`; lines for unscheduled IDs are ignored), and `complete?` is true only with a matching `done N` trailer. `ArenaResult#sgf` builds the SGF from the moves; `test/fixtures/arena/` pairs arena lines with the move nodes of twogtp SGFs of the same games. `stats` (figures in `ruby/experiment_stats.rb`, output in `ruby/stats_report.rb`), `ranking`: viewers. `multi`: rotates between several experiments.
- `lib/`: the network code every program links, built once as `lib/libann.a`. `genann.c` and `genann.h` are upstream GENANN v1.1.1, unchanged (license in `lib/GENANN-LICENSE`); to update GENANN, copy the new upstream files over them. Evo's additions live in `ann.h` and `ann.c`: the PCG `GENANN_RANDOM`, the genes (`ann_genes`, their ranges, `ann_default_genes`, `ann_genes_invalid`, and the genes line `ann_print_genes_line`), the features (`ann_features`, `ANN_FEATURES` with each move feature's group and starting weight, the clamps, `ann_default_features`, `ann_features_invalid`, and the board sides `ANN_MIN_SIDE`/`ANN_MAX_SIDE`), the feature groups, their names in fixed order, and the input layout's counts (`ANN_GROUP_*`, `ANN_GROUP_NAMES`, `ann_feature_count`, `ann_layout_inputs`; see `features.c` under `engine/`), and `ann_binary_read`/`ann_binary_write` for the `.ann` format with the activation table. Programs include `ann.h`, never `genann.h`. `lib/test.c` (`make test` in `lib/`) tests GENANN and the `.ann` round trip. `lib/minctest.h` is the test framework for `lib/` and `evolve/`.
- `pcg-c/` is an upstream submodule (`imneme/pcg-c`). Do not edit it.

## Things that trip agents up

### Engine and network files

- `evo NETWORK.ann` starts at board size 6, so send `boardsize` before `genmove`. Without exactly one file argument it prints a usage message and exits 1; a file that is missing or holds no network makes it exit 1 at startup with a message naming it.
- `boardsize` answers `? unacceptable size` for a size the loaded network does not fit, and `genmove` answers `? network does not fit the board` if no fitting `boardsize` came first. The process keeps running. `engine/enginetest.sh` (`make test`) checks a whole GTP session, and `engine/gtp_test.c` (`make test`) what evo's GTP commands leave in Brown's state, and that `place_free_handicap` plays the network with its features.
- The engine answers `name` with `Evo`.
- The `.ann` format (`lib/ann.h`), version 2, holds everything a GENANN network is, plus its genes and its features: the magic `EVOANN`, the format version (2), the sizes inputs, hidden_layers, hidden (always 0 without hidden layers: normalized on write, required on read), and outputs, a code for the hidden and the output activation (every activation GENANN offers has one, in `ANN_ACTIVATIONS`), the genes (`ann_genes`: `copy_chance`, `weight_changes`, `weight_step`, `activation_rate`, `structure_rate`) as doubles, then the features (`ann_features`): a uint32 mask of feature groups (`ANN_GROUP_*`, 0 for none), `feature_step` as a double, and one double weight per move feature of the groups (F = `ann_feature_count`, in `ANN_FEATURES`' order), then the weights as doubles: 86 + 8F bytes before the weights. All numbers are little-endian and fixed-size, so files are portable. Reading rejects a wrong magic or any version but 2 (version 1 files, from before the features, are no longer read), an unknown activation, genes that are not finite or lie outside their ranges (`ANN_*_MIN`/`_MAX` in `lib/ann.h`; `weight_changes` runs from 1 to the network's total weights), a mask with a bit that is no group, a `feature_step` outside [1e-4, 1] or a feature weight outside [−10, 10] (or not finite), outputs that are not a square board of `ANN_MIN_SIDE` to `ANN_MAX_SIDE` points a side plus pass (2 to 23, Brown's `MIN_BOARD`/`MAX_BOARD`, which `generate_move.c` checks at compile time), inputs other than `ann_layout_inputs(groups, points)` for that board, and a file that is too short or too long. Writing refuses missing or invalid genes or features, but does not check the shape against a board (`evolve/test.c` writes small networks of other shapes). `ann_binary_read(in, genes, features)` takes NULL for either when the caller does not need it; `ann_binary_write(ann, genes, features, out)` requires both. `ann_default_features(groups)` gives `feature_step` 0.01 and the hand-set starting weights (`ANN_FEATURES`: hane, cut, edge, and near_last +0.05, capture +1.0, saves_atari +0.8, self_atari −1.0). For now the runner creates every network without groups (it passes `none` to `initial-population`), `evolve` gives the child its picked parent's features unchanged (copy, crossover, and mutation alike), and `evo` and `arena` play with the features they read (see `genmove`). An experiment created before version 2 keeps its own copied executables, which still read its version-1 networks, but nothing built since does, and such an experiment is not supported.
  - A network for board size N has N²+1 outputs (pass last) and `ann_layout_inputs(groups, N²)` inputs: N²+1 without groups (komi first), 1 + 12·N² + 1 with all (974 on 9×9).
  - `engine/example.ann` is a 9×9 test fixture with 2×2 hidden neurons, cached sigmoid activations, the default genes, no feature groups (the default `feature_step`), and 418 weights. It is not a trained player.
- Move choice takes the highest output. It is deterministic for a given network and position.
  - `initial-population` and `evolve` take an optional seed as their last argument; the same seed gives byte-identical output. Without one they seed from `time(NULL)` plus an address.
- Runs are reproducible from the experiment seed (the `seed` setting; `SetupExperiment` generates and saves one if it is missing). `ruby/seeds.rb` derives every other seed from it and a label: the initial population, each child (`birth`, generation, index), parent selection, tie order and colors per round, a per-game GNU Go `--seed` for the referee and GNU Go players (`Seeds.gnugo`, added to a command by `Seeds.with_gnugo_seed`), in the tournament and in the benchmark, and the benchmark openings. Two runs with the same seed, even with parallel games, produce the same networks, pairings, moves, rankings, and benchmark results; only the date in the SGF headers differs. Losing a game on time would still differ.
- Besides `games`, the experiment database records `births` (each network's parents, operator, differing weights, seed, and SHA-256 of its `.ann`, and from migration 010 the picked `parent`, `structure`, `activation_changed`, and its genes line as `layers`, `width`, `act_hidden`, `act_output`, `copy_chance`, `weight_changes`, `weight_step`, `activation_rate`, `structure_rate`; generation 0 has operator `initial`, genes, and no parent, structure, or activation_changed; a differs count is NULL for a parent of another shape, so readers such as `ExperimentStats` handle NULL) and `rankings` (each generation's standings, kept current after every game; final once the generation is done).
- Brown's own `final_score` is unreliable on arbitrary positions: an empty 9×9 board scores `W+87.5`. Use the arena's `tromp_taylor_score` or the referee's result.
- The build uses `-march=native`. Binaries are for the local machine only.
- macOS ships GNU make 3.81, which compares timestamps to the second. A C file edited and rebuilt within the same second can leave the old object in place, so a quick edit-rebuild-test loop (such as checking that a test catches a mutant) may run a stale binary. Delete the `.o` files before rebuilding in that case.

### Game results

- A GoGui `.dat` file is tab-separated: `GAME RES_B RES_W RES_R ALT DUP LEN TIME_B TIME_W CPU_B CPU_W ERR ERR_MSG`.
  - Columns can be empty, so split on tabs. The runner and the benchmark do this in `ruby/game_result.rb`.
  - The runner saves twogtp's stderr to `PREFIX.err` next to the `.dat` file while the game runs. Only stderr says which program crashed ("Black program died" or "White program died").
- Each experiment stores its opponents, its benchmark panel, and its scoring when it is created (tables `opponents`, `benchmark_opponents`, and `scoring`, from `SetupExperiment::DEFAULT_OPPONENTS`, `DEFAULT_BENCHMARK`, and `DEFAULT_SCORING`), and the runner reads them from there, so changing the defaults only affects new experiments. By default every win is worth 1 point, whether the loser is a network or a bot, a draw 0, and the odd player out in a round sits out with 0. `scoring['rules']` is the version of the scoring logic (`RunGeneration::SCORING_RULES`); bump it when `score_game` or `GameResult` change what counts, and an experiment begun under other rules refuses to run. The bots play in the ranking like networks, and against each other, on purpose: their place in the ranking shows how the networks compare to them. Parents are chosen by tournament selection (`select_parent` in `ruby/run_generation.rb`): draw `tournament_size` networks (setting, default 3) with replacement and keep the highest score. Only the order of scores matters, and equal scores pick uniformly.
- Every game is area-scored with the experiment's komi (the `komi` setting, a multiple of 0.5 from −50 to 50, default 6.5, so a margin is never 0 without a draw). The runner passes it as `-komi` to every `gogui-twogtp` command, tournament and benchmark, and twogtp sends it to both players and the referee; the arena gets it as KOMI. The referee, `GameResult::REFEREE`, is GNU Go with `--chinese-rules` (the runner appends its `--seed`); GNU Go players keep their own rules. An experiment created before the setting has no `komi` and refuses to load.
- Scoring rules (agreed with the owner, in `score_game`, `ruby/game_result.rb`, and `ruby/arena_result.rb`):
  - The scorer decides: in the tournament, the arena's Tromp–Taylor count for a game between two networks, and the GNU Go referee (Chinese rules) for a game with a bot; in the benchmark, always the referee. A win (`B+` or `W+`) counts, including games stopped by the move limit, which the arena counts as the board stands, dead stones included.
  - A draw gives no points.
  - A network that crashes loses, whatever the referee said, and so does a network the arena cannot play (missing, unreadable, or not fitting the board). If neither network of an arena game can play, the game fails (`arena: neither network can play`).
  - These give no points and are logged, with the reason in their row's `failure` column: a crashed external bot, a missing referee score (`?`), any other GoGui error (an illegal move is blamed on the program that rejected it, not the one that played it), a missing or empty `.dat` file, and an arena game without a valid result line (`arena: no result`).
  - Failed games are never retried, so a broken setup stays visible.
- For a GoGui game, check `RES_R` and `ERR`, not only whether the game finished. A crashed player shows only in `ERR`, and a crashed referee only as `?` in `RES_R`. `scripts/smoke-external-tools.sh` checks both. Keep it that way when changing it.
- Brown and AmiGo play deterministically. The 5 Brown and 10 AmiGo "instances" are copies of the same opponent, so replaying a pairing with the same colors adds no information.
- GNU Go seeds its random choices from the clock unless it gets `--seed N`. The runner always passes one; outside the runner, compare GNU Go behavior with a fixed seed.

### Running experiments

- On a first run, `mise run run NAME` prompts on STDIN for settings. To start without prompts, create the experiment first; `SetupExperiment::SETTINGS` lists every setting with its default and its type (a whole number, an even whole number, or a number, and its range; `mise run new-experiment` without arguments shows them). A value that does not parse strictly is refused when the experiment is created, and a prompt asks again. The database stores settings as strings; `SetupExperiment.parse` turns them into Integers and Floats on every load, so the runner never converts them itself, and test settings must be typed too:
  ```sh
  mise run new-experiment NAME --board-size 9 --population-size 4 --hidden-layers 1 --layer-size 10 \
    --cross-over-rate 0.5 --game-length 10 --max-moves 200 --tournament-rounds 1 --keep-every 0 --seed 3
  mise run run NAME 4 one-generation
  ```
  That runs one generation of 10 pairings (9 games plus a bye for the odd player out) in about a second, which makes it a good smoke run. With seed 3, one game is between two networks and goes to the arena, and 8 go through GoGui (25 Sep 2026); with most seeds the 4 networks meet only the 15 bots, and the arena plays nothing. `--keep-every 0` skips the benchmark, which would otherwise add 60 games at generation 0. Delete `experiments/NAME` afterwards. Running it again breeds and plays the next generation. `experiments/` is gitignored.
- `hidden_layers` and `layer_size` are generation 0's shape. `meta_rate` is the τ of self-adaptive mutation, and the `initial_*` settings are the genes every generation-0 network starts with (ranges = the clamps in `lib/ann.h`). `initial_weight_changes`, when not given, is computed at creation from the generation-0 shape as max(1, 0.0004 × total weights) (a `SetupExperiment::Derived` default, computed from the settings before it on both the prompt and the `new-experiment` path) and stored, so a later formula change never alters an existing experiment; a value above the network's total weights is refused. `max_hidden_layers` (default 4) and `max_layer_size` (default 200) bound the shapes structural mutation can reach; the generation-0 shape must lie within them (`max_layer_size` is checked against `layer_size` only when `hidden_layers` is above 0), and a shape above them is refused on every path: the prompts ask again, `new-experiment` fails, and loading fails. So networks of one experiment differ in shape: from generation 1 on, a mutated child can gain or lose a layer or a neuron per layer, and its `births` row has its `structure` and its new `layers` and `width`. Nothing in the runner, the arena, or the benchmark assumes the generation-0 shape except `initial_weight_changes`' check and the check that `initial-population`'s genes lines have that shape. A seeded run that exercises the genes quickly:
  ```sh
  mise run new-experiment NAME --board-size 9 --population-size 12 --hidden-layers 1 --layer-size 10 \
    --cross-over-rate 0.5 --game-length 10 --max-moves 200 --tournament-rounds 3 --keep-every 2 \
    --benchmark-games 2 --initial-structure-rate 0.3 --initial-activation-rate 0.2 \
    --max-hidden-layers 3 --max-layer-size 20 --seed 4242
  ```
  Six generations of it (concurrency 4; 25 Sep 2026) produced all but one kind of structural change, shapes from 1×9 to 2×11, no failed game, 2.5–4 s per generation and 13–20 s with a checkpoint's benchmark, and the same births (every column), networks, games, rankings, and benchmark rows on a second run with the same seed. With the defaults (`initial_structure_rate` 0.02, crossover rate 0.5) a generation of 20 sees a structural change only every few generations, so a run meant to explore shapes needs a higher starting rate. Loading a database that lacks a setting fails with "… is missing".
- An experiment directory holds only `experiment.sqlite3`, the scratch directory `work/`, and the executables. The runner works inside `work/`, which it empties at the start of every generation, and calls `../evo`, `../arena`, `../evolve`, and `../initial-population`. They are **copies** of the build output, made on the experiment's first run once its settings are known, so a rebuild does not change an experiment that has started; to run new code, start a new experiment. The Ruby runner is not copied: it runs from the checkout, so an experiment whose executables take other arguments than the runner passes cannot resume. One started before the genes settings (`meta_rate`, `initial_*`) is such a case: its settings lack them and its `initial-population` and `evolve` take the old arguments. Once the provenance is recorded, a missing executable stops the run instead of being copied again. The `provenance` table records what they were built from: the git revision, whether the checkout had uncommitted changes, and the external tools release.
- `RunGeneration#play_round` splits a round's games: the bye is scored at once; games between two networks go to the arena (`../arena`, scored by Tromp–Taylor, `scorer` `tromp_taylor`) in at most `concurrency` chunks, each one `WorkerPool` job with the files `arena-K.txt` (schedule, IDs from the game's file prefix), `arena-K.out`, and `arena-K.err`; games with a bot go to `gogui-twogtp`, one job each. The wait loop counts jobs. When a chunk finishes, every game in it is scored (a network that cannot play loses; a game without a valid line fails with `arena: no result`, including every game after the arena died, the chunk's files are read as UTF-8 whatever the locale, and bytes that are not UTF-8 are replaced before parsing), stored, and ranked, then the chunk's files are deleted. What an arena row holds is in the bullet on game results below; the chunk's overhead share is floored at 0. `SCORING_RULES` `2` is the version that scores network games in the arena.
- Everything but a game's files in progress lives in `experiments/NAME/experiment.sqlite3`: the settings, and each generation's round, players, standings (`rankings`), and pending games. `RunGeneration#data` loads a generation's state in the shape `data.json` used to have, and `save_data` replaces it in one transaction after every game. On resume, `setup_complete` skips creating or breeding the population, the runner starts from the last generation in the database, and a generation's games are skipped only once `round` reaches `tournament_rounds`. A checkpoint's benchmark runs after that check too, so a resumed checkpoint finishes its benchmark. `RunGeneration#call` returns `:already_done`, which makes a `one-generation` run go on to the next generation, only when the generation played no tournament game and no benchmark game.
- Ctrl-C during "Generating population" kills the running `evolve` too, and the runner exits quietly as it does in the tournament (with exit 130 and a message when evolve's status shows the interrupt before the trap ran). Nothing is lost: the children bred so far are in `births` and `networks`, but the generation's setup is saved only after the last child, so a resume breeds every child again from the first, with the same seeds and the same parent draws, and overwrites those rows. An interrupted and resumed run gives the same births, networks, games, rankings, and benchmark rows as an uninterrupted one (checked twice mid-breeding, 25 Sep 2026).
- The runner passes `-force` to twogtp, which deletes an existing `PREFIX.dat`. A game that was queued but not yet scored when the runner stopped, through GoGui or in the arena, is replayed from scratch on resume, and its `.err` is rewritten.
- Generation 0 names networks `0001.ann`, `0002.ann`, and so on. Later generations use `0.ann`, `1.ann`, and so on.
- Game results live in `experiments/NAME/experiment.sqlite3`, through `ExperimentDatabase` (`ruby/experiment_database.rb`, Sequel on SQLite). After scoring a game, the runner writes its row and deletes the game's files (`.dat`, `.sgf`, and `.err`; an arena chunk's files once all its games are stored). The row holds:
  - the players, the winner or failure, the length, the result (`referee_result`: GNU Go's for a GoGui game, the Tromp–Taylor count for an arena game), the error message (GoGui's, or `move limit exceeded` for an arena game stopped by the limit), and stderr (for an arena game, the chunk's, only when the game failed);
  - `scorer`, who decided the game: `gnugo` for a GoGui game refereed by GNU Go, `tromp_taylor` for an arena game. `ExperimentDatabase#record` refuses a row without one, and rows from before migration 009 got `gnugo`;
  - the timings. For a GoGui game, `duration` is the wall-clock seconds of the whole `gogui-twogtp` run, measured by `WorkerPool`, and `time_black`/`time_white` are the seconds each player spent answering `genmove`, from twogtp's `TIME_B`/`TIME_W`, to a tenth; the rest of `duration` is the referee, the JVM, process starts, and the other GTP commands, plus a 3 s wait twogtp adds when a player crashed. For an arena game, `duration` is the game's own time in the arena plus an equal share of its chunk's overhead (the chunk's wall time beyond its games', such as starting the arena and loading the networks), so a generation's durations still add up to its worker seconds, and `time_black`/`time_white` are the summed move times, to a tenth. Rows from before migration 005 have no timings;
  - the SGF, only for every `keep_every`-th generation (setting, default 10; 0 keeps none); an arena game's is built from its moves (`ArenaResult#sgf`).

  Rows are keyed by generation, round, and players, so a replayed game replaces its row.
- The schema changes only through Sequel migrations in `db/migrations/`. The runner applies pending ones when it opens the store. Add a new numbered migration for a schema change; never edit one that has run.
- `stats` and `ranking` only read: they open the experiment database read-only, so they can run beside the runner.
- Networks live in the `networks` table (the `.ann` bytes). The runner writes the current generation's networks into `work/` to play them, and the parents into `work/parents/` to breed, because both generations name their networks `0.ann`, `1.ann`, and so on. A generation's networks are dropped, in the same transaction that saves the next generation's setup, unless it is a `keep_every`-th generation. To inspect a network, export it: `ExperimentDatabase#export_networks(generation, directory)`.
- `stats NAME` prints the tables once and exits; `--watch` redraws them every 5 s until Ctrl-C; `--csv` prints one row per generation.
  - Tables: Generations (the latest 50), then for the latest 10 generations Genes (each gene's median, the median layers, width, and total weights, and the min and max rows for the latest generation with births), Shapes and activations (the three most common of each), and Breeding and bots (most children of one parent, parents without children, structural changes, and per bot group the best copy's rank by score with the networks above it in brackets), then the checkpoints' Benchmark.
  - Children per parent count selection: a crossover counts for both parents, a mutation or copy for the picked parent, out of the previous generation's ranked networks. The Parents column (`population.distinct_parents`) instead counts whose weights survive. Bot ranks go by score (1 + players with more points), so tied players share a rank whatever order the ranking broke the tie in. A bot group is a stored opponent (`opponents` table); its copies are named with a copy number (`Brown1`).
  - The CSV header is fixed per experiment: the tournament and population columns; `genes.GENE.min|median|max` for the five genes; `shape.layers|width|weights.min|median|max` (summaries, not one column per shape, which would vary); `activation.hidden|output.NAME` for all six activations; `structure.OP` for the five ops (`none` included); `parents.max_children|childless|used`; `bots.best_rank`, `bots.networks_above`, and the same two per stored bot group (`bots.Brown.best_rank`); then `benchmark.network`, `benchmark.complete`, and per opponent of the stored panel, color, and outcome (`benchmark.Brown.black.win`). Experiments with the same opponents and panel compare column by column; cells a generation lacks (genes and parents before migration 010, structure and parents in generation 0, a group with no ranked copy) are empty.
- `ExperimentStats` computes the figures (a Hash per generation) and `ExperimentStats::Report` formats them; neither prints on its own. A checkpoint counts as finished only once its benchmark is complete: stored rows equal `benchmark_games` times the opponents from `CheckpointBenchmark.opponents_for`, the same rule the runner plays by, so change it there only.
- `ranking` and `multi` loop forever. Run them with a timeout or in the background.
- Games run on a `WorkerPool` (`ruby/worker_pool.rb`): `concurrency` threads, created once per experiment, each running a `gogui-twogtp` game or an arena chunk through `system`; `next_finished` returns a job's identifier, its wall-clock seconds, and its `Process::Status`. On Ctrl-C the running games stop, the pool starts no queued game (`WorkerPool#halt`, called from the trap in `RunExperiment`), and the runner exits without scoring, leaving the unfinished games (a whole arena chunk, too) pending in the database, so resuming replays them. Ctrl-C reaches the games as well as the runner, and a killed job can come back before the trap has set `$stop_now`, so the runner (tournament and benchmark) also exits without scoring a job whose status `WorkerPool.interrupted?` calls interrupted: killed by SIGINT or SIGTERM, or exiting 130 or 143 (128 plus the signal), as `gogui-twogtp`'s JVM does on Ctrl-C. Without the flag set it says on stderr which game or chunk was interrupted and exits 130 (after Ctrl-C with the flag set the runner exits 0, though `mise run run` itself reports 130 because mise gets the SIGINT too; `multi` ignores the status either way), so killing one hung game stops the run and leaves the game pending. A shell running a command that SIGINT killed kills itself with SIGINT, and the arena dies of it, so both show as signaled. Any other crash of the arena, such as SIGKILL or SIGSEGV, is scored: its games without a valid line fail with `arena: no result`.
- GNU Go 3.8 needs `scripts/patches/gnugo-3.8-gg-sort-empty.patch`. Without it, clang builds abort in `final_score` and during level 10 move generation. GCC builds happen to work either way. When changing how external tools are built, bump `release_id` in `scripts/install-external-tools.sh` so existing installs rebuild, then run `mise run verify`.
- The installer downloads only from the GitHub release named in `mirror_url` in `scripts/install-external-tools.sh`, never from upstream. `scripts/external-tools.txt` lists each archive's SHA-256 and upstream URL. To change an archive, edit the manifest, give `mirror_url` a new release tag (a published release's files should not change under the same tag), bump `release_id`, and run `mise run mirror-external-tools`. That task fetches from upstream and uploads to the release.

### Benchmark

- `CheckpointBenchmark` (`ruby/checkpoint_benchmark.rb`) measures progress apart from the tournament. `RunGeneration#call` runs it after the tournament of every `keep_every`-th generation (the checkpoints, whose networks are kept); with `keep_every` 0 it never runs.
- It plays the top network of the generation's final ranking (the first entry that is not a bot) against the stored panel `benchmark_opponents`, in order. `kind` is `bot` (run by `command`), `initial_champion` (generation 0's top network), or `previous_checkpoint` (the top network of generation minus `keep_every`). Generation 0 plays the bots only, and `previous_checkpoint` is skipped when it would be generation 0, which `initial_champion` already covers.
- Each opponent gets `benchmark_games` games (setting, even, default 20), half with each color: opening `k` is played once with each. The openings (`Openings.moves`) have `benchmark_opening_moves` stones (setting, default 4), drawn from the experiment seed and `k`, never orthogonally adjacent, so they are the same at every checkpoint and checkpoints compare. They go to twogtp as `-openings work/benchmark/openings/k/`.
- twogtp counts opening stones as moves, so the runner passes `-maxmoves` as `max_moves` plus the opening's stones, and the stored `length` includes them.
- With `benchmark_opening_moves` 0 there is no `-openings`, and the games against deterministic opponents (Brown, AmiGo, networks) repeat: only the GNU Go games differ, through their per-game seed.
- Scoring follows the tournament's rules from the benchmarked network's side: the referee decides, a crashed network (benchmarked or opponent) loses, a draw has no winner, and a crashed bot, a missing referee score, another GoGui error, or a missing `.dat` is a failure with no winner.
- Results go to `benchmark_games`, one row per game keyed by generation, opponent, opening, and `network_color` (the benchmarked network's). `winner` is `network`, `opponent`, or nil; `network` is the benchmarked network's name and `opponent_network` the opposing one as `generation:name`. The other columns are those of `games`; no SGF is kept.
- On resume it plays only the games with no row. A row is stored before the game's files are deleted, so a crash between the two does not replay the game. Ctrl-C exits before scoring, as in the tournament, also when the interrupted game is back before the trap has run.
- Its files live in `work/benchmark/`: the exported networks as `GENERATION-NAME`, each game as `OPPONENT-OPENING-COLOR` (`.dat`, `-0.sgf`, `.err`), and the openings.

### Performance

- The tournament's bots are only Brown and AmiGo. GNU Go referees there but does not play: GNU Go opponents, at level 0 as much as level 10, set most of a generation's wall time while early networks are far too weak for them. It comes back through the opponent ladder in `PROJECT_NOTES.md`. GNU Go level 0 does play in the benchmark.
- A checkpoint's benchmark with the default panel, on 9×9 with concurrency 2 (25 Sep 2026), took 52–69 s, most of it the 20 games against GNU Go level 0. The tournament of 4 networks in the same generations took 2–19 s.
- One generation profiled on macOS (25 Sep 2026, 8 cores, patched GNU Go): 9×9, 20 networks with 1 hidden layer of 100, 10 rounds, `max_moves` 200, seed 1, concurrency 4, `keep_every` 0, generation 0, with the 15 Brown and AmiGo copies: 170 games, two runs each.
  - With the arena: 8.5–8.7 s of wall time, about 1,200 games a minute. The 69 games between two networks took 0.9–1.4 s of summed `duration` (median 0.005 s, 90th percentile 0.010 s). The 101 GoGui games with a bot took 27 s (median 0.27 s, 90th percentile 0.31–0.33 s, slowest 0.5 s), nearly all the game time.
  - With every game through GoGui (`main` before the arena, same settings): 25.7–28.1 s of wall time, 65–73 s of summed `duration`, median 0.30–0.34 s, 90th percentile 0.41–0.50 s. In the slower run the network games took 39 s of the 73, and the slowest (up to 4.4 s) ended early and left the referee an unfinished position.
  - A network answers in under a tenth of a second, so its `time_black`/`time_white` read 0.0, and a GoGui game's whole `duration` is overhead: JVM, referee, and process starts.
  - Each round waits for its slowest job. The per-round lower bound, max(slowest game, summed durations / concurrency), came to 7.1 of the 8.5 s; the rest is setup (the initial population; the profile was generation 0, so no breeding), per-game bookkeeping, and jobs packing unevenly onto the workers.
  - GNU Go against a network took about 7 s a game at level 0 or 10 (up to 13.7 s against AmiGo), measured before the arena with both levels in the tournament's panel: once GNU Go opponents return, each round waits for such a game.
  - Storage: a network's `.ann` is 8 × total weights + 86 bytes (header, genes, feature mask, and `feature_step`) + 8 per feature weight (none yet), total weights as `SetupExperiment.total_weights` counts them. On 9×9, 1×10 is 14 kB; the default bounds' largest, 4×200 (153,682 weights), 1.23 MB; 4×200 on 19×19, 2.1 MB. A kept checkpoint stores every network of its generation, so 20 networks at 4×200 on 9×9 take about 25 MB per checkpoint.
  - A 20-generation run with the default genes and bounds (25 Sep 2026, same machine): 9×9, 20 networks of 1×50 (8,332 weights), crossover rate 0.5, `max_moves` 200, 5 rounds, `keep_every` 5, `benchmark_games` 10, seed 2026, concurrency 4. A generation (85 games, breeding included) took 3.9–4.6 s; a checkpoint 19.8–21.5 s, about 16 s of it the benchmark (30–50 games, most of the time against GNU Go level 0); 2.4 min in all. The database ended at 8.8 MB: 1.33 MB of networks per kept generation (4 checkpoints plus the current generation), 0.28 MB of SGFs from the checkpoints, and little else. SQLite does not shrink the file when a generation's networks are dropped, so it grows in steps of a generation's networks and reuses the freed pages afterwards.
  - Features cost about 10× in the arena, still little: 90 games between 10 seeded 9×9 1×50 networks (`initial-population` seed 11, `max_moves` 200, mean length 84–87) took a median of 0.0003 s per game without groups and 0.0033 s with all (974 inputs, 52,932 weights), about 3 and 37 µs per move (26 Sep 2026).
  - Engine inference is negligible: a 9×9 network with 3 hidden layers of 400 neurons (about 387k weights) answered 1,000 `genmove` commands in 0.21 s (24 Sep 2026). Engine start and exit took about 10 ms.

## Working conventions

- Fix defects test-first: write a test that fails, then fix.
- Commits: imperative, sentence-case subject (for example "Build GNU Go with common symbols on Linux"), with a body that explains why.
- Branches: `fix/…`, `chore/…`, `docs/…`.
- PRs: this is a personal repo with no Jira, so titles and bodies carry no ticket key. The body is one short paragraph that starts with the why, plus a line on how the change was verified.
- Open and update every PR by following `docs/pull-requests.md`: tests, the sweep for stale text, the review loop and its rules, and the CI check.
- Run any change bigger than one PR by `docs/orchestration.md`: agree it with the owner, write the plan in `plans/` (gitignored), have it reviewed, then approved by the owner, give each step to a fresh subagent with a review of each commit, open the PRs, and report once at the end.
- CI (`.github/workflows/ci.yml`) runs on every pull request, whatever its base (so stacked PRs get checks), and on pushes to `main`, on Ubuntu, with one job per kind of check: `c-tests` (`test-c`), `ruby-tests` (`test-ruby`), and `smoke-matches` (`setup-experiments`, `doctor`, `smoke`). Branch protection on `main` requires these jobs by name, so renaming or adding a job also needs the protection rule updated. CI caches the gems (keyed on `Gemfile.lock` and `mise.toml`) and the built external tools in `.local/evo-tools` (keyed on the installer, the manifest, and `scripts/patches/`). Both keys also include the runner image, because the caches hold compiled code. A change to how the tools build has to change one of those files, or CI keeps using the old build. Bumping `release_id` does that. Local setup is usually macOS with Apple clang, so code that builds GNU Go or other external tools has to work with both clang and GCC. A green local `verify` says nothing about Linux; wait for CI. Docker reproduces CI's toolchain locally when a change needs checking before that: `gcc:14` for the C build, `ubuntu:24.04` for its `mawk` and `dash`. Copy `pcg-c` into the image as plain files: its `.git` points back to the checkout it came from, so a `git clean` inside the copy deletes that checkout's build output.
